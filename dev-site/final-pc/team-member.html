    Team Member Pages

    Developer note

    One page. The person’s record decides what it shows.

    There are two HTML files here and they are not two designs. They are the same template at both ends of its content range — a maximum record and a minimum one — so what a thin profile does is visible next to what a full one does. The expanded file carries licenses, listings, testimonials, awards and a headshot. The minimal file is a placeholder record with none of that: one panel, so no sub-nav is drawn at all; no rail cards, so no rail; and no photograph, so the identity band falls back to PC’s contact placeholder. Same band, same panels, same rail — different amounts of record.

    A section with no data is absent, not empty. The sub-nav is built from the panels that exist, so a person with no sold listings has no Sold tab and the remaining tabs close the gap. Never render an empty tab, an empty rail card, or a “nothing here yet” message. The same rule governs every rail block.

    Do not build two templates. Build one and drive it from the record. The split below exists so both ends of the range can be seen at once — the fullest possible profile and the leanest one.

    These pages are visual mockups. Every form control is inert and the styling comes from one stylesheet, pc.css. The build specification — the field list, the conditional sub-nav, the rail and the responsive ladder — is developer-team-member.md.
